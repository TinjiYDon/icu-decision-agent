## 3. 完成的代码修改

### 3.1 严格分层的数据集划分

修改：`domain/models/split.py`

原实现虽然标注为 stratified，但在合并类别并重新打乱后按整体位置切片，不能严格保证 train、validation、test 的阳性比例一致。

本次改为两阶段 `StratifiedShuffleSplit`：

1. 严格分出 train 与 holdout；
2. 在 holdout 内严格分出 validation 与 test；
3. 全程使用 stay_id，禁止同一 stay 跨集合；
4. 固定 `seed=42`，保证重复运行得到相同划分。

新增数据检查：

- 缺少 stay_id 或 label 时拒绝划分；
- 同一 stay 存在冲突标签时拒绝划分；
- 标签为空时拒绝划分；
- 标签不是二分类 0/1 时拒绝划分；
- 样本不足以形成三个集合时拒绝划分。

split manifest 新增：

- `stratified`；
- 每个集合的阴性数和阳性数；
- 每个集合的阳性率；
- 每个 stay_id 的集合归属。

### 3.2 full dump 安全训练入口

修改：`application/train.py`

新增命令：

```powershell
$env:PYTHONPATH = (Get-Location)
.\.venv\Scripts\python.exe -m application.train --from-existing
```

该入口只读取 full dump 已恢复的：

- `feat.sample_matrix`；
- `label.mortality_12h`。

它不会从 Layer0 重新构建特征和标签，避免在 `source: mock` 或 Layer0 不可用时覆盖 94,458 行 full dump 数据。

原来的默认命令仍保留，用于确实具备正确 Layer0 数据源时执行完整重建。

### 3.3 不平衡分类评估模块

新增：`domain/models/evaluation.py`

新增指标：

- ROC-AUC；
- PR-AUC；
- Brier score；
- Log loss；
- Precision；
- Recall / Sensitivity；
- Specificity；
- F1；
- TP、FP、FN、TN 混淆矩阵；
- 分位数校准曲线数据。

由于阳性率只有 2.22%，不再只依赖 ROC-AUC 或 Accuracy 描述模型。

### 3.4 阈值选择规则

修改：`domain/models/lgbm.py`

新增规则：

1. 只使用 validation 数据选择最大 F1 阈值；
2. 阈值确定后固定；
3. 将同一个阈值应用到 test；
4. test 不参与阈值或超参数选择。

同时保留 0.5 默认阈值指标，用于展示默认阈值为何不适用于当前模型。

## 5. 基线训练结果

### 5.1 判别与校准指标

| 指标 | Validation | Test |
|---|---:|---:|
| ROC-AUC | 0.6729 | 0.6935 |
| PR-AUC | 0.0393 | 0.0413 |
| Brier score | 0.0483 | 0.0477 |
| Log loss | 0.2180 | 0.2157 |

旧记录 `auc_val=0.711 / auc_test=0.682` 来自非严格分层实现。严格分层后，validation 与 test 的类别比例更稳定，因此后续实验统一使用本次结果作为基线。

### 5.2 阈值结果

默认阈值 0.5 在 validation 和 test 上均无法预测出阳性，Recall 为 0，不能使用。

仅使用 validation 最大化 F1 后得到阈值：

```text
0.3458
```

固定后应用到 test：

| 指标 | Validation | Test |
|---|---:|---:|
| Precision | 5.46% | 5.34% |
| Recall | 19.52% | 18.33% |
| Specificity | 92.31% | 92.60% |
| F1 | 0.0853 | 0.0827 |

测试集混淆矩阵：

| 项 | 人数 |
|---|---:|
| TP：正确发现阳性 | 77 |
| FP：错误报警 | 1,366 |
| FN：漏掉阳性 | 343 |
| TN：正确识别阴性 | 17,105 |

## 6. 实验结论

1. 当前模型具备一定排序能力，但阳性识别能力较弱。
2. Test PR-AUC 为 0.0413，只高于 2.22% 的阳性率基准，提升有限。
3. 当前模型在实验阈值下只能召回 18.33% 的阳性患者。
4. 当前概率没有经过校准，不能把模型分数直接解释为真实死亡概率。
5. 当前页面中的 0.2/0.4/0.7 建议档位不是经过临床验证的阈值。
6. 只有年龄、性别和科室的 6 个静态特征不足以支撑临床部署。

因此，本次交付定位为“可复现的工程与算法基线”，不是临床可用模型。

## 7. 标签审计

已新增 `docs/LABEL_AUDIT.md`，审计结论如下：

- 当前标签使用 ICU `intime` 与 `patients.dod`；
- 日期级 `dod` 无法精确判断 12 小时时窗；
- 当前配置对“ICU 死亡”和“院内死亡”的描述不统一；
- full dump 不包含原始 `dod/deathtime`，无法在 dump 内计算误标率；
- 当前 2,099 个阳性可用于工程复现，但尚不满足临床研究标签口径。

下一版标签应优先使用精确 `admissions.deathtime`，明确 ICU 死亡或院内死亡，并报告新旧标签变化。
