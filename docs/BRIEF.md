# decision 项目到底在做什么（人话版）

> 版本：v1.0（2026-11-03）｜对象：不熟悉本项目的老师/同学/评审
> 一句话：**ICU 分诊台只有少量“复核名额”；我们研究的是——用两套不同的“死亡日期”记录，同一套复核策略会被评成完全不同的好坏，所以要先统一标签语义，再谈策略好坏。**

---

## 1. 一个类比：ICU 分诊台

想象 ICU 每小时给每个病人算一个“未来 12 小时恶化概率” p（0~1）。

分诊台只有三种动作：

| 动作 | 含义 | 代价 |
|---|---|---|
| **放行** | 不额外复核，保持日常监测 | 如果病人真恶化，漏掉（代价最大） |
| **复核** | 占用一个当班复核名额，人工看一眼 | 占用人力（名额有限） |
| **报警** | 直接升级处理 | 如果误报，打扰医护 |

问题：**名额有限**（比如当班只能复核 20% 的人），**漏报代价远大于误报**。所以不能“都报警”，也不能“都放行”。

---

## 2. 两套“死亡日期”记录，是全部混乱的根源

MIMIC 里有两个死亡时间字段：

| 标签 | 是什么 | 阳性率 | 特点 |
|---|---|---|---|
| `deathtime` | 精确死亡时间 | 1.19% | 严格：只有真正在 12 小时内死亡才算阳性 |
| `dod` | 死亡日期（只到天） | 2.34% | 粗：当天死亡的人全算阳性，哪怕不是 12 小时内 |

关键事实：**dod 里有 5,401 个阳性是 deathtime 里没有的（占 dod 阳性 48.9%）**。也就是说，用 dod 评估时，很多“当天死亡但不在 12 小时内”的人被算成了“该抓的人”。

后果：
- 同一套复核策略，用 dod 评估时“抓得更准”（yield 0.1158），用 deathtime 评估时只有 0.0320；
- 分别按两套标签去挑阈值，挑出来的复核名单只有 **24% 重合**（Jaccard 0.2429）。

**所以“复核策略好不好”不是策略自己的属性，而是“策略 + 标签定义”的属性。**

## 3. 图里的旧框架 vs 现在的主线

你发的那张图（资源约束下的预警—复核协同框架）是**旧框架**：

```
风险预测 → 校准/预算 → 序贯复核 SBR → 放行风险控制 PAC
```

这套东西我们做过（H9 SBR、PAC），但查新后发现**已经撞车**（conformal deferral、LTT 报警抑制等），所以现在只当**工程基线**，不再当创新主张。

现在的主线只有一句话：

> **先固定标签语义，再评估复核策略；并给出对“两套标签”都稳的阈值选择。**

对应两个东西：
- **LARE**：同一策略在两套标签下评估，比较 yield / 漏检 / 复核名单重合度；
- **LAR-Policy**：选一组阈值，使“两套标签下最坏的那个代价”最小。

## 4. 目标函数、约束、取舍（用具体数字讲）

### 4.1 代价

举例（默认参数）：
- 漏掉一个真恶化：代价 4
- 误报一个：代价 1
- 复核一次：代价 0.2

期望代价 ≈ `4 × 漏检率 + 1 × 误报率 + 0.2 × 复核率`。

### 4.2 约束

- **复核预算 K**：复核 + 报警的人不能超过 20%（K=0.2）；
- **放行风险 α**：放行的人里，真阳性的比例（漏检质量）不能超过 5%（α=0.05）。

### 4.3 旧 SBR（工程基线，不是创新）

在“最多复核 K 次”的前提下，决定“现在复核、还是等下一小时的新化验再决定”，用动态规划算期望代价最小。公式是 Bellman 递推，本质是“现在花一次复核，还是等更多信息”。

### 4.4 PAC 放行控制（工程基线，不是创新）

选两个阈值：低于 `τ_low` 放行、高于 `τ_high` 报警、中间复核。用 Hoeffding 上界保证“放行区漏检 ≤ α”不是碰巧：

```
上界 = 经验漏检率 + sqrt( log(1/δ) / (2n) )
只有上界 ≤ α 才算“可行”
```

n=4000、α=5% 时上界半径约 0.0343，直接把 α 吃掉了 2/3 → **不可行**；要到 n≈47k 才可能。

### 4.5 LARE（现在的主线）

不做新算法，只做**评估**：
- 同一个分数、同一个策略；
- 分别用 dod / deathtime 两套标签算 yield、漏检、复核名单；
- 比较两套结果的差距。

### 4.6 LAR-Policy（第二点，方法）

在两套标签下同时选阈值，目标：

```
最小化  max( 在 dod 下的代价, 在 deathtime 下的代价 )
约束：  复核+报警 ≤ K
        两套标签的放行漏检都 ≤ α
```

这就是“鲁棒”：不追求某一套标签下最优，而是追求“换一套标签也不至于太差”。

## 5. 五步链路：每一步在比什么

```
第1步 算 p：LightGBM 给每个病人一个 0~1 的风险分
第2步 做动作：按阈值把病人分成 放行 / 复核 / 报警
第3步 算结果：在两套标签下，分别算 抓到了多少、漏了多少、复核了谁
第4步 做比较：yield 差多少？复核名单重合多少（Jaccard）？
第5步 选策略：LAR-Policy 在两套标签的“最坏代价”里选最小
```

判断标准：
- 如果两套标签下 yield 差很大、Jaccard 很低 → **标签歧义会改变评估结论**；
- 如果 LAR-Policy 的 max_regret 很小 → **存在一套“换标签也不亏”的阈值**；
- 如果效应为零 → 也是一个结论（负结果），不硬吹。

---

## 6. 鲁棒性到底怎么实现

不是“对分布偏移鲁棒”，而是两层很具体的鲁棒：

1. **对标签版本鲁棒**：目标函数取 `max(dod 代价, deathtime 代价)`，即换标签也不崩；
2. **对样本量鲁棒**：可选 Hoeffding 上界，数据不够时不允许说“可行”（n=4000/α=5% 会直接判不可行）。

## 7. 同类文献在做什么、我们撞了什么

| 方向 | 代表工作 | 他们假设 | 我们差在哪 |
|---|---|---|---|
| 选择性预测/转交 | conformal deferral（Sci Rep 2026） | 标签固定 | 我们问“标签时间粗化会不会改变评估” |
| 报警抑制 | LTT 给有害抑制率上界 | 标签固定 | 同上 |
| 证据门控 | EGCL / OpenMed / QCC | 证据溯源与放行状态机 | 我们不做新门控 |
| 人机适当依赖 | appropriate reliance 框架 | 人因指标 | 我们只借用指标 |

**我们唯一没被占的缝**：`标签时间歧义 × 复核评估`，以及“对两套标签都稳的阈值选择”。

## 8. 什么样的产出能证明有效

不是“准确率更高”，而是四张表：

1. **同一策略两套标签**：yield 差、漏检、复核名单 Jaccard（合成 0.2446 / MIMIC 0.2429）；
2. **标签专属阈值漂移**：τ 差多少、名单换多少；
3. **LAR-Policy**：robust_cost、max_regret、可行率（合成 0.15995/0.0134；MIMIC 0.0708/0.0039）；
4. **消融/敏感性**：K、α、粗化强度变化时结论是否稳定；零效应也如实写。

## 9. 为什么 pi 反复报错（不是 pi 不行，是指令有问题）

实际踩的坑：
1. **表名写错**：任务包写 `paper_feat.sample_matrix`，但第一次跑连到了 `mimic` 库；实际数据在 `icu_decision` 库的 `paper_feat/paper_label` → `UndefinedTable`。
2. **没有预检**：派单前没检查“库/表/模型文件/DSN”是否存在。
3. **文档口径分裂**：旧文档讲 SBR/PAC，新文档讲 LARE；pi 读到两套说法，输出自然打架。
4. **没有 CI**：新模块只靠本地跑，错了没人拦。
5. **运行器自身有 bug**：`care` 字段名不实、`high_acuity` 场景无效、db 源 seed 不是真随机——这些都是跑完才发现的。

修正做法：
- 派单前跑**预检脚本**（库/表/列/模型/DSN）；
- 每个任务包先 `--smoke`，通过再跑全量；
- 单一口径文档（旧文档归档），UI/叙事同步；
- 新模块进 CI 白名单；
- pi 只改代码，实验由 lead 验收后才跑。

## 10. 四个问题的解法

| 问题 | 解法 |
|---|---|
| 1 阶段逻辑混乱 | 建 `STAGE.md`：S0 预测 → S1 标签审计 → S2 LARE 评估 → S3 LAR-Policy；旧 SBR/PAC 标“工程基线”，旧文档进 archive |
| 2 介绍难懂 | 用本文件（分诊台类比 + 五步链路 + 四张表）；重画框架图：旧 SBR/PAC 用虚线，LARE/LAR-Policy 用实线 |
| 3 实现方法不对/缺自查 | 预检 → smoke → 单测 → CI → lead 验收；任务包写死 schema，不再让 pi 猜表名 |
| 4 路径规划欠佳 | 两周：第1周统一叙事+预检+CI；第2周跑真实 LARE/LAR-Policy + 消融 + 成稿；期间不引入新点子 |

## 11. 术语小抄

| 词 | 人话 |
|---|---|
| p(s,h) | 病人在入科后 h 小时、未来 12 小时恶化的概率 |
| 放行/复核/报警 | 不额外看 / 人工看一眼 / 直接升级 |
| K | 当班最多能复核+报警的比例 |
| α | 放行的人里允许漏掉的真阳性比例 |
| dod / deathtime | 死亡日期（粗）/ 精确死亡时间（严） |
| LARE | 在两套标签下评估同一复核策略 |
| LAR-Policy | 选一组“换标签也不至于太差”的阈值 |
| max_regret | 和“针对该标签专门调优”相比，最坏多亏多少 |
| Hoeffding | 用样本量算“最坏可能漏多少”的上界 |
