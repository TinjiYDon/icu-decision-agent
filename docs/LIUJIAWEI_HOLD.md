# 为何暂不合 `liujiawei`（仍可优化模型）

> L3 决策 · 2026-08-02 · **不是否定优化**，是合入方式要对

## 一句话

队友在推「更多特征 + 更强筛选 → AUC≈0.89」。方向可以要；**裸分支不能直接合 main**，否则会把不可复现、可能偷看未来的结果锁进默认基线。

## 风险在哪（实现性）

| 点 | 说明 |
|----|------|
| **预测时刻** | main 契约：`hour_index=0` 入科可知。分支注释/特征含 **入 ICU 后 1h** 的 vital/lab/GCS/升压药等。若答辩口径仍是「入科即预警」，这叫**时间窗泄漏**（不是故意作弊，是契约不一致）。 |
| **AUC 跳变** | 0.69 → 0.89 很大。可能是真增益，也可能是时刻/标签/划分变松。未证明前不能当「官方数字」。 |
| **数据底座** | 当前 P0-full dump 只有 **6 个特征**。合入后队友 `restore` + `--from-existing` **会断**，要先重建 Layer1 dump。 |
| **工程分叉** | 相对 main **无 merge-base**；旁路 `train_final_model.py`；PR#6 的分层评估/测试曾被删或弱化 → 强合成本高。 |

## 能否优化模型？

**能。** 推荐路径（一次 PR，避免碎改）：

1. **先定契约**：预测时刻是 `intime` 还是 `intime+1h`？写进 `features.yaml` + STATUS。
2. **只合「合法窗口」特征**：入院前/入科瞬间可知的 lab、Elixhauser、人口学等；1h 治疗变量单独一组并标注。
3. **走主训练入口**：`application.train` + 保留 `evaluation.py` / leak 测试；附可复现命令与新 dump。
4. **对照表**：同一 split 上报 ROC / **PR-AUC** / Brier（阳性≈2%，只报 ROC 会乐观）。

在满足以上之前：**main 继续用 PR#6 弱基线（≈0.67/0.69）**，诚实、可复现。
