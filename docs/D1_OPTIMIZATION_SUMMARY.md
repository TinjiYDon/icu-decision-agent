# D1 优化工作完整总结

## 背景

我们有一个 ICU 死亡风险预测系统，核心链路是：
`MIMIC数据库 → LightGBM模型预测风险 → SHAP特征归因 → RAG文献检索 → LLM生成解释报告`

D1 实验的目标是证明：加了 RAG 文献检索和专业提示词之后，AI 生成的解释比纯靠 LLM 自己编的更准确、更有依据。

---

## 一、引用校验修复（效果最大）

**问题**：以前判断"引用的数值对不对"用的是固定容差 ±0.05。
- 例子：患者肌酐 1.2 mg/dL，文献写 1.3，判为不匹配 → 实际上 1.2 和 1.3 在医学上几乎一样
- 例子：BUN=45，文献范围 7-20，差太远自然不会匹配，但规则也判不对
- 另外，引用校验只看截断的 200 字符片段，经常关键信息被截断，导致误判

**修复**：
- 改成按数值类型自动选容差：
  - 比值型（如 SOFA 分）：容差 ±0.5
  - 百分比型（如 SpO2%）：容差 ±2
  - 浓度型（如乳酸 mmol/L）：相对容差 ±15%
  - 计数型（如 WBC）：相对容差 ±20%
- 校验改用完整父 chunk（parent_content），不再用截断的 snippet
- 效果：引用有效率从 44.9% 提升到 53.3%，提升 8.4 个百分点

---

## 二、RAG 检索路由扩展

**问题**：以前只给 LLM 路由了 6 个主题（SOFA、ARDS、休克指数、乳酸、GCS、脓毒症），BUN、肌酐、白细胞、血小板这些 ICU 日常高频指标完全没有检索路径，LLM 拿到不精准，解释质量自然差。

**修复**：
- 路由从 6 个扩展到 18 个，新增：
  - BUN（血尿素氮）、肌酐、尿酸
  - WBC（白细胞）、PLT（血小板）、CRP（C反应蛋白）、PCT（降钙素原）
  - MAP（平均动脉压）、SpO2、FiO2
  - INR（凝血指标）、胆红素、白蛋白
  - 钾、钠
- 所有新增路由优先指向 threshold 类别（有正常/危急值范围的文献），而不是 general 类别
- 效果：更多特征能关联到权威医学文献，解释中有具体数字和范围的比例大幅提升

## 三、提示词重构

### 3.1 详细解释要求

**问题**：以前 prompt 没有明确说要多详细，LLM 经常两句话就把一个因子解释完，信息量很薄。

**修复**：
- System Prompt 新增第 6 条规则：每个特征解释必须包含四个要素
  1. 实测值与正常范围/危急值的比较
  2. 该异常在 ICU 死亡风险中的临床意义
  3. SHAP 贡献的方向和幅度
  4. 引用来源编号
- 给出具体示例：「模型统计观察：乳酸实测值 4.2 mmol/L，高于危急值 4.0 mmol/L，根据 SSC 2026 指南[REF-01]……」
- User Prompt 要求每个因子解释不少于 60 字
- 效果：单条解释从几十个字变成 100-300 字的详细解读

### 3.2 因果词白名单

**问题**：以前把"提示""关联""多见于""常见于"这些医学术语也一律替换成"与...相关"，解释读起来像机器翻译，非常生硬。

**修复**：
- 拆分成两个列表：
  - **强制替换**（危险因果词）：导致/引起/诱发/造成/引发/致 → 替换为"与...相关"
  - **保留不动**（医学术语白名单）：提示/关联/多见于/常见于/伴随/相关/见于
- 效果：解释读起来更自然，更像临床医生的表述习惯

### 3.3 前缀从"必须"改为"建议"

**问题**：强制要求每个特征以"模型统计观察："开头，有时候反而显得刻意和重复。

**修复**：从"必须"改为"建议"，给 LLM 一定的表达自由度。

## 四、新增评估指标（D1.3）

**问题**：原来只有 4 个指标能区分"好不好"，SHAP 对齐率两边都是 1.0（没区分度），过度承诺率 RAG 反而更高（反直觉）。

**修复**：新增 3 项 Human-aligned 指标：

1. **风险一致性**（risk_consistency）：检查 SHAP 方向（升/降风险）和解释文字描述是否矛盾
   - 例子：SHAP 说乳酸升高→升风险，解释写"乳酸升高降低了风险" → 不一致，扣分

2. **临床术语密度**（clinical_term_density）：统计解释中使用了多少标准医学术语 vs 口语
   - 例子：用"乳酸"不用"血液里的酸"，用"WBC"后用全称"白细胞"

3. **可读性分数**（readability_score）：检查解释长度是否在合理区间 [100, 300] 字符
   - 太短（<100字）= 信息不足
   - 太长（>300字）= 信息密度低
   - 落在区间内得满分

## 五、其他工程改进

### 5.1 UI 兼容旧报告
旧的 7 项指标报告和新的 10 项报告格式不一致，加了兼容性处理，旧报告不会报错，只是显示 warning 提示重新生成。

### 5.2 可读性评分区间调整
因为提示词改详细了，理想解释长度变长，可读性评分的合理区间从 [80, 250] 调整为 [100, 300]。

### 5.3 移除"解释安全"导航页
D1 评测结果对日常使用没有直接价值，从 Streamlit 前端导航栏移除了该页面，但代码和 CLI 命令保留，方便后续跑评测。
