# AI临床部署的伦理与监管框架

## FDA AI/ML医疗器械监管框架

【适用：AI医疗产品监管理解】

**De Novo分类路径**：
- 适用于无同等物（predicate）的新型低风险医疗器械
- 本项目模型如商业化，需走De Novo路径
- 要求：临床有效性和安全性数据、风险分析、软件验证

**Good Machine Learning Practice（GMLP，2023）**：
FDA发布的AI/ML软件最佳实践框架，包含五大支柱：
1. **多学科团队**：临床专家+数据科学家+监管事务
2. **数据集质量**：代表性、完整性、标注准确性
3. **模型开发**：合理的特征工程、充分的验证、可解释性
4. **性能监测**：持续监控漂移、不良事件报告
5. **风险管理**：FMEA分析、减轻策略、临床监督

**本项目合规状态**：
- 当前为研究原型（Research Use Only），非医疗器械
- 论文投稿需遵循TRIPOD-AI和STARD-AI报告规范
- 未来临床部署需通过IDE（Investigational Device Exemption）申请

## 可解释AI的临床责任边界

【适用：AI辅助决策的责任归属】

**临床责任分配原则**：
- AI输出仅供参考，不替代临床判断
- 最终决策权在主治医师（attending physician）
- 医生需对采纳或拒绝AI建议负责
- AI系统提供方需对产品缺陷承担法律责任

**"清晰幻象"风险**：
- SHAP等事后解释方法可能给人"模型透明"的假象
- 临床医生可能过度信任AI输出的"解释"
- 缓解措施：明确声明解释的局限性，提供不确定性量化

**本项目安全设计**：
- 明确声明："模型发现仅供参考，不可替代临床判断"
- 不提供诊疗建议，仅提供风险分层和解释
- coverage_note说明已解释特征的贡献占比，体现不确定性
- fallback_mode（RAG不可用时降级为通用解释）确保服务可用性

来源：Topol E. Nat Med. 2019;25(1):44-54.
来源：FDA. Guidance: Artificial Intelligence/Machine Learning (AI/ML)-Based Software as a Medical Device. 2023.

## 数据隐私与去标识化

【适用：患者数据保护】

**HIPAA Safe Harbor方法**：
- 移除18种个人标识符（姓名、SSN、日期等）
- MIMIC-IV已按要求去标识化（date shift ≥180天）
- 本项目研究数据存储在受保护的服务器上

**再识别风险**：
- 组合少量特征（年龄+性别+ICU类型）即可识别个体
- 差分隐私（Differential Privacy）可在数据发布时添加噪声
- 本项目为内部研究用途，不涉及数据公开发布

**伦理审查**：
- MIMIC-IV数据使用已通过MIT IRB豁免
- 本项目研究已通过相关伦理审批
- 未来临床部署需重新进行伦理审查

## AI公平性与偏见检测

【适用：模型公平性评估】

**偏见来源**：
- 数据偏见：训练数据缺乏某些人群代表性
- 算法偏见：特征工程引入系统性偏差
- 部署偏见：模型在不同人群中性能差异

**本项目公平性检查**：
- 按年龄分层：老年（>65岁）vs 中青年（≤65岁）
- 按性别分层：男 vs 女
- 按careunit分层：Medical ICU vs Surgical ICU
- 报告各亚组的AUC和Brier score差异

**公平性指标**：
- 群体AUC差异 <0.05：可接受
- 群体Brier score差异 <0.02：可接受
- 如差异过大，需考虑分组建模或公平性约束

来源：Obermeyer Z, et al. Science. 2019;366(6464):447-453.
