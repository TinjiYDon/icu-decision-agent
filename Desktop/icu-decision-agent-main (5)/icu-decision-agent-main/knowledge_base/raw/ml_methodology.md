# 机器学习方法论：类别不平衡处理与模型校准

## 类别不平衡处理方法

【适用：ICU死亡率预测中的极端不平衡】

**问题描述**：
ICU死亡率通常在10-30%之间，而本项目正样本率仅2.34%（11,039/472,290），属于极端类别不平衡。

**常用方法对比**：

| 方法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **类权重（scale_pos_weight）** | 对少数类赋予更高权重 | 简单有效，LightGBM原生支持 | 权重选择依赖经验 |
| **SMOTE** | 少数类合成过采样 | 平衡训练集分布 | 可能引入噪声；时间序列不适用 |
| **ADASYN** | 自适应合成采样 | 关注难分类样本 | 计算成本高 |
| **Focal Loss** | 降低易分类样本权重 | 专注于hard samples | 需要调整gamma参数 |
| **欠采样** | 随机删除多数类样本 | 减少训练时间 | 丢失信息 |
| **集成方法（EasyEnsemble）** | 多次欠采样后集成 | 保留信息+平衡分布 | 计算开销大 |

**本项目选择**：
使用 `scale_pos_weight = n_negative / n_positive ≈ 31.4`
- LightGBM原生支持，无需额外采样
- 保持原始数据分布，不引入合成噪声
- 等效于对少数类赋予约31倍权重

**验证**：
- 未使用SMOTE（时序数据不适合随机过采样）
- 使用分层抽样（stratify=y）确保各fold正负比例一致
- 通过PR-AUC和F1-score综合评估，而非仅看AUC

## SHAP值解读指南

【适用：SHAP结果临床解释】

**Shapley值基础**：
源自合作博弈论，衡量每个特征对预测结果的边际贡献。

**局部解释**：
对于一个样本x：
f(x) = E[f(x')] + Σ φ_i(x')
其中φ_i是第i个特征的SHAP值，E[f(x')]是基线值（所有样本的平均预测）。

**解读规则**：
- φ_i > 0：该特征值高于平均水平，推动预测值上升（正向贡献）
- φ_i < 0：该特征值低于平均水平，推动预测值下降（负向贡献）
- |φ_i|越大：该特征对当前预测的影响越大
- Σφ_i = f(x) - E[f(x')]：所有特征SHAP值之和等于预测偏差

**全局解释**：
- SHAP摘要图（summary plot）：展示所有样本的特征重要性和影响方向
- 均值|φ_i|排序 = 特征重要性排序
- 颜色表示特征值高低（红色=高值，蓝色=低值）

**注意事项**：
- SHAP值基于统计关联，不等于因果效应
- 特征共线性可能导致SHAP值分配不均
- 树模型SHAP（TreeSHAP）与样本SHAP略有不同，TreeSHAP更快且更精确

来源：Lundberg SM, Lee SI. Advances in Neural Information Processing Systems. 2017;30.

## 模型校准：为什么需要校准

【适用：临床部署前的模型验证】

**区分度 vs 校准度**：
- 区分度（Discrimination）：模型区分阳性和阴性样本的能力（AUC）
- 校准度（Calibration）：预测概率与真实发生率的一致性

**校准不佳的后果**：
- 预测10%风险的患者实际死亡率可能是5%或20%
- 导致临床决策失误（过度治疗或治疗不足）
- 风险分层阈值失效（低/中/高风险档位的实际分布偏移）

**校准评估方法**：
1. **校准曲线**：横轴=预测风险分箱，纵轴=实际事件率
2. **Hosmer-Lemeshow检验**：p>0.05表示校准良好（但样本量大时过于敏感）
3. **Brier Score**：0=完美校准，1=最差校准；本项目0.040表示良好校准
4. **校准斜率**：理想值=1.0；<1表示预测范围被压缩，>1表示过度区分

**校准方法**：
- **Platt缩放**：logistic回归校准
- **Isotonic回归**：非参数校准，适合大样本
- **分箱校准**：按预测风险分箱后重新标定

**本项目现状**：
- Brier score=0.040（calibration_slope待报告）
- 风险档位设计（低<5%，中5-15%，高>15%）基于训练集分位数
- 未来需外部验证校准性能

## 交叉验证与数据泄露预防

【适用：确保模型评估可靠性】

**按stay_id分层划分**：
- 禁止：同一stay的样本出现在train和test中（数据泄露）
- 正确做法：先按stay_id分组，再将group分到train/val/test
- 本项目：0.7/0.1/0.2 split，seed=42，stay_id唯一标识

**常见泄露源**：
1. 未来信息泄露（look-ahead bias）：使用预测时间点之后的数据
2. 重复样本：同一患者多次出现在train和test
3. 特征工程泄露：在整个数据集上拟合预处理步骤后split
4. 群体级信息：使用患者级别的聚合统计量作为特征

**本项目预防措施**：
- 特征构建严格限制在预测时刻之前（pre-ICU + [intime, intime+h)窗口）
- stay_id分层划分防止重复患者
- 预处理（缺失值填充、标准化）仅在train集fit，transform val/test
- 标签定义在预测时刻之后（intime+h到intime+h+12h）

来源：Stott JE, et al. BMJ. 2018;361:k1849.
